================================================================================
SHIFT SYSTEM ISSUE - DETAILED ANALYSIS
================================================================================

PROBLEM:
--------
User says "shift wala acche se kaam nahi kar raha hai" (shift system not working properly)

Looking at the screenshot, I can see:
- Academy shift: 13:00 - 19:00, Late Threshold: 15 min
- Academy Shift Second Half: 15:00 - 19:00, Late Threshold: 15 min
- DPS Shift: 08:10 - 15:10, Late Threshold: 15 min
- DPS Shift First Half: 08:15 - 12:15, Late Threshold: 15 min

POTENTIAL ISSUES IDENTIFIED:
-----------------------------

1. SHIFT ASSIGNMENT PROBLEM
   - Employees may not have shifts assigned in employee_shifts table
   - Attendance records may have NULL shift_id
   - When shift_id is NULL, late threshold calculation fails

2. MULTIPLE SHIFTS FOR SAME INSTITUTION
   - There are 2 Academy shifts (full and second half)
   - There are 2 DPS shifts (full and first half)
   - System may be confused about which shift to use

3. ATTENDANCE RECORDS WITHOUT SHIFT_ID
   - If attendance.shift_id is NULL, the calculate_attendance_status function cannot work
   - Late threshold comparison requires shift information

4. EFFECTIVE DATE RANGE ISSUES
   - Shift assignments have effective_from and effective_to dates
   - If dates don't cover current period, shift won't be found
   - get_employee_shift function may return NULL

5. INSTITUTION VS SHIFT MISMATCH
   - Employee's institution_assignment may not match their assigned shift
   - Example: DPS employee assigned to Academy shift


ROOT CAUSE ANALYSIS:
--------------------

The shift system has TWO separate concepts:

A) SHIFT DEFINITION (shifts table)
   - Defines shift timings and rules
   - Example: "Academy" shift 13:00-19:00

B) SHIFT ASSIGNMENT (employee_shifts table)
   - Links employees to shifts
   - Has effective date ranges
   - This is where the problem likely is!

MOST LIKELY ISSUES:

1. Employees don't have active shift assignments
   - employee_shifts table is empty or has expired assignments
   - effective_from/effective_to dates don't cover current period

2. Attendance records created without shift_id
   - When employee checks in, shift_id should be set
   - If get_employee_shift returns NULL, attendance.shift_id becomes NULL
   - Without shift_id, late threshold cannot be calculated

3. Check-in code may not be setting shift_id correctly
   - AttendanceCheckIn component gets shift info
   - But may not be storing shift_id in attendance record


HOW TO DIAGNOSE:
----------------

Run the debug_shift_assignment_issue.sql file to check:

1. How many employees have active shift assignments?
2. How many attendance records have NULL shift_id?
3. Are effective_from/effective_to dates correct?
4. Does get_employee_shift function return correct shifts?


SOLUTION STEPS:
---------------

STEP 1: Verify the problem
   - Run debug_shift_assignment_issue.sql
   - Check Step 4: Employees WITHOUT shift assignment
   - Check Step 7: Attendance records with NULL shift_id

STEP 2: Fix missing shift assignments
   - Go to "Employee Shift Assignment" page
   - Assign shifts to all employees
   - Make sure effective_from is in the past
   - Leave effective_to as NULL (ongoing)

STEP 3: Fix existing attendance records with NULL shift_id
   - Create migration to backfill shift_id
   - Use employee_shifts table to find correct shift for each date
   - Update attendance records

STEP 4: Ensure check-in code sets shift_id
   - Verify AttendanceCheckIn.tsx is setting shift_id
   - Check that shiftInfo.shift_id is being used

STEP 5: Recalculate late flags
   - After shift_id is fixed, recalculate all is_late flags
   - Use the fixed calculate_attendance_status function


QUICK FIX MIGRATION:
--------------------

If attendance records have NULL shift_id, create a migration to:
1. Find employee's active shift for each attendance date
2. Update attendance.shift_id with correct shift
3. Recalculate calculated_status and is_late


PREVENTION:
-----------

1. Make shift assignment MANDATORY before employee can check in
2. Add validation in check-in code to ensure shift exists
3. Add database constraint to prevent NULL shift_id in attendance
4. Show warning in UI if employee has no shift assigned
